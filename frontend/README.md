# Hotel Reservation — frontend

Next.js/React/TypeScript приложение в том же репозитории, что и Spring Boot. Реализованы каталог → выбор комнаты → вход → расчёт → явное подтверждение → свои брони → детали → отмена. Это локальная реализация основного сценария; публичное размещение и финальная браузерная приёмка ещё не выполнены.

## Что находится внутри

- `src/app`: главная, каталог/отель, `/demo/booking/review`, вход и кабинет `/account/bookings[/id]`, админка `/admin`.
- `src/components`: переиспользуемые React-компоненты, сохранённые условия брони и demo notices.
- `src/lib/api-schema.d.ts`: сохранённые в Git типы из `../docs/api/openapi.json`; при изменении контракта перегенерируйте их вместе с JSON.
- `api-client.ts`: same-origin session/CSRF, типизированные booking operations без автоматических повторов POST.
- `booking-flow.ts`: подтверждение и восстановление неопределённого результата.
- `proxy.ts`: ограниченный Next Route Handler к фиксированному Spring backend.
- `tests/fixture-api.mjs`: только явно выбранный UI test double; в обычном приложении fallback на него отсутствует.

Цены, доступность, право/срок отмены и окончательный статус определяет backend. Новые брони показывают сохранённый snapshot; у legacy неизвестные цена/гости остаются неизвестными. Клиент не считает принятой бронь по нажатию кнопки.

## Постоянный локальный запуск (основной режим)

Из корня репозитория: `./dev start`; из этой папки: `npm run local:start`. Один раз выполните `npm ci`, запустите Docker Desktop и установите Java 21. Откройте http://127.0.0.1:3000/. Логин `local-user`, пароль — в `../.local/login.txt` (закрытый файл). Остановка: `npm run local:stop` либо Ctrl+C; состояние: `npm run local:status`. Каталог, аккаунты, сессии и брони сохраняются в отдельных именованных томах; время работы не ограничено. Рабочая БД и .env не используются. Подробности — в корневом README.

Для этого режима не нужен Maven manual-test: запускается настоящий JAR с отдельным профилем local. Next использует прежний защищённый от внешних origins development HTTP-адаптер. Перезапуск не подменяет данные начальными примерами. Для тестов с гарантированно временными данными по-прежнему используйте `dev:isolated` ниже. Одновременно эти режимы не запускаются.

## Посмотреть интерфейс без HTTPS

Нужен Node.js 22+, npm. Установите зависимости из этой папки:

```sh
npm ci
```

Терминал 1:

```sh
node tests/fixture-api.mjs
```

Терминал 2:

```sh
FRONTEND_QA_MODE=1 \
BROWSER_BACKEND_ORIGIN=http://127.0.0.1:18081 \
PUBLIC_ORIGIN=http://127.0.0.1:3000 \
npm run dev -- --webpack
```

Откройте http://127.0.0.1:3000/demo/hotels. Пометка тестового API видна на всех страницах. Учебный вход `qa-user` / `qa-only-password`; профиль `demo-user` взят из контрактного примера. В этой среде quote/бронь/отмена существуют только в памяти фикстуры. Cookie `qa-fixture-session` не моделирует защищённую JDBC-сессию. Перезапуск фикстуры сбрасывает только её временные данные. Остановка — Ctrl+C в обоих терминалах.

## Настоящий backend в изолированном окружении

Нужны JDK **21**, Docker и установленные npm-зависимости. Сначала остановите другой Next dev из этой папки. Укажите JAVA_HOME на свой JDK 21:

```sh
npm run dev:isolated
```

Скрипт сам создаёт временные PostgreSQL/Kafka/MongoDB Testcontainers, запускает реальный Spring Boot на случайном loopback-порту, добавляет два вымышленных отеля и обычного тестового USER, затем запускает Next на http://127.0.0.1:3000/demo/hotels. Рабочая БД/Compose volumes не используются; данные из .env для подключения к рабочей БД не нужны.

Вход только для этой временной среды: `frontend-browser-user` / `local-browser-test-password`. Не используйте эти данные для публичного сервиса. Они не создают администратора.

**Не запускайте другой Maven-процесс, пока работает этот preview**: target/ общий. `FrontendLiveIntegrationTest` помечен manual, исключён из обычных тестов и включается скриптом явно. Ctrl+C останавливает Next и завершает временный backend; содержимое контейнеров не предназначено для сохранения. Preview ограничен тремя часами. Путь к backend.log и ready.json печатается при запуске, сам ready-файл доступен только владельцу и не попадает в Git.

Локальный запуск теперь использует **HTTP**, без сертификатов и предупреждений браузера. Скрипт включает серверный `LOCAL_HTTP_MODE=1` только для loopback frontend/backend в development. В этом режиме Next-адаптер преобразует `__Host-hotel-session` backend в локальную `hotel-local-session` без Secure и переводит имя обратно при запросах к Spring. HttpOnly, SameSite=Lax, CSRF и точная проверка Origin сохраняются. Cookie выхода преобразуется тем же способом. Backend и его настройки безопасности не меняются. В production и для внешних адресов HTTP-режим отклоняется.

Для воспроизводимой автоматической проверки возьмите путь ready.json из вывода работающего preview:

```sh
node scripts/verify-live.mjs /absolute/path/ready.json - /tmp/hotel-http-result.json
```

Проверка использует реальный Next → Spring API: каталог, локальную HttpOnly cookie/JDBC-сессию, Origin/CSRF, quote, создание, result lookup/bodyless replay, fence, свои брони, отмену/освобождение дат и logout. Это проверка сетевого протокола, а не кликов браузера. Для прежнего HTTPS-окружения скрипт поддерживает `PUBLIC_ORIGIN=https://localhost:3443` и путь сертификата вторым аргументом с полной TLS-валидацией.

## Обычная конфигурация

```sh
cp .env.example .env.local
npm run dev
```

`BROWSER_BACKEND_ORIGIN` — фиксированный внутренний origin backend, `PUBLIC_ORIGIN` — точный внешний origin сайта. HTTP разрешён только в явно выбранном локальном режиме разработки. Это серверные параметры, без NEXT_PUBLIC_. При отсутствии backend/v2 каталог показывает ошибку. Самостоятельно запускать старую рабочую БД ради frontend не нужно: сначала backup/schema review из `../README.md` и отдельное тестовое окружение.

Никакие session ID, пароли или quoteToken не сохраняются в localStorage/sessionStorage/URL. Перед CREATE в sessionStorage записываются только UUID операции, owner ID и версия формата. Если ключ не удалось сохранить, POST не отправляется. После перезагрузки сначала проверяется прежняя операция; чужой owner не используется для recovery. 404 result не разрешает новую отправку: доступна явная проверка/fence. Неопределённый результат не превращается в ошибочное сообщение «бронь не создана». После server-confirmed FAILED нужны новый расчёт и новое согласие.

Next сначала проверяет внешний Origin, затем переводит его во внутренний Origin для фиксированного backend. Spring независимо проверяет session/CSRF. Idempotency-Key передаётся в заголовке. Произвольные Authorization/X-Forwarded-* не пересылаются; redirects/HTML errors upstream не раскрываются. API — private/no-store, demo/auth/account — noindex. В публичном окружении необходимо изолировать backend от обхода адаптера и определить доверенную source-IP политику для rate limits; сейчас backend видит IP адаптера.

## Проверки и оставшиеся этапы

```sh
npm run generate:api
npm run typecheck
npm test
npm run build
```

53 frontend-теста: client protocol, CSRF, returnTo, proxy и booking workflow, включая double click, lost response/404, fence, reload/owner switch, запрет CREATE без хранилища, повреждённый recovery context и поздний ответ после ухода со страницы. Production build компилирует все маршруты. Backend отдельно прошёл unit/HTTP и полный integration verify.

Автоматический доступ к вкладке ранее был заблокирован политикой инструмента браузера; полноценный прогон кликов FE-03 остаётся незавершённым. HTTPS для локального просмотра отключён по запросу пользователя. Не следует считать сетевую приёмку эквивалентом браузерным E2E. Управление каталогом/изображениями и frontend CI реализованы локально. Далее нужны mobile/accessibility/browser checks (включая новые admin-формы), email/восстановление, backup/restore, администрирование броней/статистики и deployment. Публичная регистрация пока закрыта, оплаты нет.

## Обновлённый дизайн — 22 октября 2026

Локальный интерфейс переработан по визуальной структуре hotel.tutu.ru: белая шапка, фотообложка, поисковая панель, фиолетовые действия и горизонтальные карточки с реальными фильтрами цены/сортировки. Главная тоже получает список городов через API. Общие CSS, шапка/подвал и PropertyPhoto используются всеми экранами. Фотографии локальные: источники и лицензия — public/photos/SOURCES.md. Стоковые интерьеры явно подписаны как примеры, не фото вымышленных отелей.

Браузерный доступ в этой задаче сработал обычным CUA API. Проверены главная, поиск, фильтры/сброс/пустая выдача, страница отеля; viewport 1280 и 390 px, горизонтальное переполнение исправлено. Это ограниченная проверка редизайна, не полная приёмка booking E2E. Цена из формы нормализуется в точный Decimal API (целые рубли и запятая допустимы), округление лишних копеек не производится.


## Администратор

Для постоянной локальной среды откройте `/admin`: логин `local-admin`, пароль — в закрытом `../.local/admin-login.txt`. При входе обычным USER выйдите и смените аккаунт. Создайте отель, затем его номера; публикация управляется отдельно. JPEG/PNG до 5 МБ загружаются в черновик, затем нужно сохранить форму с alt/автором/лицензией. Скрытие сохраняет брони. После неопределённого результата сохранения сначала перечитайте объект; устаревшая версия требует сравнить изменения.

## CI frontend

В `.github/workflows/verify.yml` добавлена отдельная задача **Frontend checks** на push и pull_request. Используется Node.js 26, зависимости фиксирует package-lock.json. Кеш npm настроен по lockfile согласно [setup-node](https://github.com/actions/setup-node/blob/main/README.md). Backend-проверки остаются отдельной задачей с Java21 и Docker.

Шаги: `npm ci` → проверка API-контракта Python3 → генерация и сравнение API-типов → `npm test` → production build → `npm run typecheck`. Typecheck выполняется после build, чтобы проверить также сгенерированные Next route types. Расхождение сохранённых и сгенерированных API-типов завершает задачу ошибкой; изменённые типы нужно включать в тот же commit, что и контракт.

Канонические JSON/fixtures и валидатор находятся в **репозитории**, `../docs/api/`. Внешняя папка проекта для клонирования/CI больше не требуется. При изменении OpenAPI выполните `npm run generate:api`. Тесты и build не запускают Docker, рабочую БД или локальный сайт; HTTP-запросы в unit-тестах подменены. Это не browser E2E и не автоматическое размещение. Секреты и `.local/` для этих проверок не нужны.

Не запускайте build в папке работающего Next dev: оба пишут `.next`. Остановите сайт через `../dev stop` или проверяйте в отдельной копии. Локальная проверка CI-последовательности не является запуском GitHub Actions; облачная задача начнёт работать после отправки workflow и frontend в GitHub.
